# Remove nbdev from directlfq

## Context

`directlfq` was originally built with **nbdev**: source code lived in Jupyter notebooks
under `nbdev_nbs/` and was auto-converted to `.py` modules in `directlfq/`. The team has
since switched to editing the `.py` files directly. The notebooks were last touched in
2024 while the `.py` files have been hand-edited through 2025, so the notebooks are now
**stale** and no longer the source of truth — yet several `.py` files still carry the
misleading `# AUTOGENERATED! DO NOT EDIT!` header. nbdev tooling, config, the `nbdev_test`
CI job, and a never-published Quarto docs site all remain as dead weight that confuses
contributors.

Goal: make the `.py` files the unambiguous source of truth, salvage the genuinely useful
unit tests that currently only exist inside `nbdev_nbs/` notebooks, and remove nbdev and
its docs/site infrastructure entirely — while preserving test coverage by running the
remaining `tests/` notebooks through **nbmake** (which does not depend on nbdev).

### Notebook → .py coverage (verified)

All 6 `nbdev_nbs/` notebooks have a corresponding `.py` module, and the `.py` is
authoritative in every case:

| Notebook | Target module | .py exists | Still has AUTOGENERATED header |
|---|---|---|---|
| `02_normalization.ipynb` | `directlfq/normalization.py` | yes | yes (stale) |
| `03_protein_intensity_estimation.ipynb` | `directlfq/protein_intensity_estimation.py` | yes | yes (stale) |
| `04_utils.ipynb` | `directlfq/utils.py` | yes | no (markers only) |
| `05_visualizations.ipynb` | `directlfq/visualizations.py` | yes | no (markers only) |
| `06_benchmarking.ipynb` | `directlfq/benchmarking.py` | yes | no (markers only) |
| `08_tracefilter.ipynb` | `directlfq/tracefilter.py` | yes (test-only nb) | no |

`lfq_manager.py` and `testfile_handling.py` still carry AUTOGENERATED headers pointing at
`01_lfq_manager.ipynb` / `07_testfile_handling.ipynb` notebooks that **no longer exist** —
they are already orphaned, source-of-truth modules.

Nothing imports `directlfq/_nbdev.py` or `directlfq/_modidx.py` (verified by grep); they
are only consumed by nbdev itself.

## Approach

Work in this order so test coverage is never silently dropped: **(1) salvage tests →
(2) replace CI → (3) strip markers → (4) delete files → (5) clean config/docs → (6) verify.**

### 1. Salvage notebook unit tests into `tests/pytest/`

The `nbdev_nbs/` notebooks contain inline `assert`-based tests run today only by
`nbdev_test` (against the notebooks' own stale code, not the installed package). Port the
worthwhile ones into the real pytest suite at `tests/pytest/`, rewriting them to import
from the installed `directlfq.<module>`.

- Add `tests/pytest/conftest.py` with a fixture resolving the repo's `test_data/`
  directory (notebook tests use relative `../test_data/...` paths that must become
  absolute/fixture-based). Follow the minimal conventions already in
  `tests/pytest/test_requirements.py`.
- Create one test module per source module, porting the cells **with assertions** and any
  small inline helper functions they depend on (e.g. `create_input_df_from_input_vals`,
  `generate_randarrays`). Rewrite calls to import from the package:
  - `test_tracefilter.py` — **high value**, ~9 pure-numpy tests, copy near-verbatim from
    `08_tracefilter.ipynb`, no test data.
  - `test_normalization.py` — **high value**, ~6 tests from `02_normalization.ipynb`
    (uses `directlfq.test_utils.PeptideProfile`/`ProteinProfileGenerator`; 2 need
    `test_data/unit_tests/protein_normalization/`).
  - `test_protein_intensity_estimation.py` — ~5 tests from `03_*` (`ProtvalCutter`,
    `find_nameswitch_indices`, profile retention). **Drop** the 2 pandas/numpy "learning
    tests".
  - `test_benchmarking.py` — ~4 tests from `06_*` (`ScaledDFCreator*`); 2 need
    `test_data/unit_tests/protein_normalization/example_proteins.tsv`. Skip the
    density-plot/learning cells.
  - `test_visualizations.py` — 2 matplotlib tests from `05_*` (assert on `len(ax.lines)`);
    lower priority/fragile. Include but mark clearly.
  - `04_utils.ipynb`: only 1 real test, heavy file-I/O integration on a large fixture —
    **do not port**; note it as dropped (the `tests/` notebooks already exercise table
    loading).
- After writing, run the new tests and **delete or fix any test that references a
  function/signature that no longer exists** in the current `.py` (expected, since
  notebooks are stale). Drop tests for removed functionality rather than resurrecting it.

### 2. Replace the `nbdev_test` CI job with nbmake

`nbdev_test` (in `.github/workflows/nbdev_tests.yml`) is the only consumer of `nbdev`. It
executes every notebook in the repo. Replace it with a job that runs the `tests/`
notebooks via `pytest --nbmake` (the exact mechanism `tests/run_quicktests.sh` and
`tests/run_ratio_tests.sh` already use).

- Rewrite `.github/workflows/nbdev_tests.yml` → rename to `notebook_tests.yml`, keep the
  loose-install setup (`misc/pip_install.sh loose,dask,tests`), and replace the
  `nbdev_test` step with `python -m pytest --nbmake` over the remaining `tests/` notebook
  directories.
- When implementing, confirm the notebook set: some notebooks (`ratio_tests/`,
  `runtime_tests/`, `organellar_maps/`) need large downloaded data or long runtimes and
  are already covered by `ratio_tests.yml` / are not CI-suitable. Target the lightweight
  dirs (`quicktests/`, `normalization_tests/`, `table_reformatting/`, `learning_tests/`,
  `example_plots/`) and `log`/comment any notebook deliberately excluded — do not silently
  drop coverage. `requirements_tests.txt` keeps `nbmake`.

### 3. Strip nbdev markers from the source-of-truth modules

Remove the `# AUTOGENERATED! DO NOT EDIT! File to edit: ...` header line and all
`# %% ../nbdev_nbs/<nb>.ipynb [...]` cell-boundary comments. **Code only — no logic
changes.** Files:

- Header + cell markers: `directlfq/normalization.py`,
  `directlfq/protein_intensity_estimation.py`, `directlfq/lfq_manager.py`,
  `directlfq/testfile_handling.py`
- Cell markers only: `directlfq/utils.py`, `directlfq/benchmarking.py`,
  `directlfq/visualizations.py`

### 4. Delete nbdev source notebooks and generated index files

- `nbdev_nbs/` — entire directory (after step 1 salvage), including its nested
  `nbdev.yml`, `_quarto.yml`, `sidebar.yml`.
- `directlfq/_modidx.py`, `directlfq/_nbdev.py` (unused generated index files).

### 5. Delete docs/site infra and clean config references

Delete (none are imported or published by any workflow):

- `settings.ini`, `nbdev.yml`, `_quarto.yml`, `sidebar.yml`, `styles.css` (repo root)
- `.github/workflows/unused/nbdev_tests.yaml`, `.github/workflows/unused/deploy.yaml`
  (dead fastai nbdev/quarto CI)

Edit config that references the deleted files:

- `.bumpversion.toml` — remove the `[[tool.bumpversion.files]] filename = "./settings.ini"`
  entry. (Version source of truth is `directlfq/__init__.py` via `pyproject.toml`
  `version = {attr = "directlfq.__version__"}`; settings.ini was only kept in sync, not
  used for packaging.)
- `MANIFEST.in` — remove `include settings.ini`.
- `requirements/requirements_tests.txt` — remove `nbdev>=2.3.9` (**keep** `nbmake==1.5.3`).
- `CONTRIBUTING.md` — remove the `nbdev_install_git_hooks` instruction.
- `README.md` — update the unit-tests badge (line ~9) to the renamed workflow file, and
  rewrite the paragraph (line ~266) that claims `nbdev_nbs` holds the source and is
  converted via nbdev; replace with "source is the `.py` modules in `directlfq/`".

Leave alone: `directlfq/docs/Empty_manual.pdf` is a shipped PDF manual, unrelated to nbdev
(`doc_path` was `_docs`, which does not exist).

## Verification

1. **Imports intact after marker strip:**
   `python -c "import directlfq; from directlfq import normalization, protein_intensity_estimation, utils, visualizations, benchmarking, tracefilter, lfq_manager, testfile_handling, lfq_manager"`
2. **Salvaged tests pass:** `pytest tests/pytest` (green; any test that can't be made to
   pass against current code is dropped, not skipped silently).
3. **No nbdev residue:**
   `grep -rni "nbdev\|AUTOGENERATED\|nbdev_nbs\|notebook2script" . --exclude-dir=.git`
   returns nothing (except intentional history/CHANGELOG if any).
4. **Notebook CI step works locally:** run the new `pytest --nbmake` command from the
   rewritten workflow over the targeted `tests/` dirs.
5. **Packaging/version still works:** `pip install -e ".[tests]"` succeeds, and a
   bump-my-version dry run (`bump-my-version bump --dry-run patch`) finds all its target
   files (i.e. the removed `settings.ini` entry doesn't break it).
6. **CLI smoke test:** `directlfq lfq -i test_data/system_tests/quicktests/diann/shortened_input.tsv`
   runs (mirrors `run_quicktests.sh`).
